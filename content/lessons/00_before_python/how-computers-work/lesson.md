محاضرة نظرية: لن تكتب Python كثيرًا هنا، لكنك ستفهم **العالم** الذي يعيش فيه كودك. كل مفهوم
لاحق (المتغيرات، الملفات، الأخطاء، الأداء) يصبح أوضح عندما تعرف ما يحدث تحت السطح.

## 1. مكونات الحاسوب

:::theory title="أربعة أجزاء أساسية"
- **المعالج (CPU):** ينفّذ التعليمات، واحدة تلو الأخرى، بمليارات التعليمات في الثانية. لكنه لا
  يفهم إلا تعليمات بسيطة جدًا: اجمع رقمين، انسخ قيمة، قارن، اقفز إلى تعليمة أخرى.
- **الذاكرة الرئيسية (RAM):** مكان العمل السريع. البرنامج قيد التشغيل وكل متغيراته يعيشون فيها.
  هي **مؤقتة (volatile)**: تفقد محتواها عند انقطاع الكهرباء.
- **التخزين الدائم (storage: SSD / HDD):** أبطأ بكثير، لكنه يحتفظ بالملفات دائمًا: ملفات
  `.py`، البيانات، الصور.
- **الإدخال والإخراج (I/O):** لوحة المفاتيح، الشاشة، الشبكة، الطابعة.
:::

:::compare title="الذاكرة مقابل التخزين"
**RAM**

- سريعة جدًا (نانوثوانٍ).
- مؤقتة: تُمسح عند الإغلاق.
- سعتها محدودة (8–64 GB عادة).
- فيها: المتغيرات، الـprocess قيد التشغيل.
|||
**Storage (SSD / HDD)**

- أبطأ بآلاف المرات.
- دائمة: تبقى بعد الإغلاق.
- سعتها كبيرة (مئات GB إلى TB).
- فيها: الملفات والبرامج المحفوظة.
:::

## 2. نموذج von Neumann ودورة التنفيذ

:::theory title="البرنامج بيانات أيضًا"
معظم الحواسيب الحديثة تتبع **نموذج von Neumann**: التعليمات والبيانات تُخزَّن معًا في الذاكرة
نفسها. والمعالج يكرر إلى ما لا نهاية دورة من ثلاث مراحل:

1. **Fetch:** اجلب التعليمة التالية من الذاكرة.
2. **Decode:** افهم ما المطلوب (جمع؟ نسخ؟ مقارنة؟).
3. **Execute:** نفّذها، ثم انتقل إلى التعليمة التالية.

كل سطر Python تكتبه يتحول في النهاية إلى عدد كبير من هذه التعليمات البسيطة.
:::

:::diagram title="دورة Fetch → Decode → Execute"
flowchart LR
    F["Fetch: read next instruction from RAM"] --> D["Decode: what operation?"]
    D --> E["Execute: compute / copy / compare / jump"]
    E --> F
:::

## 3. نظام التشغيل، البرنامج، والـprocess

:::theory title="من يدير كل هذا؟"
**نظام التشغيل (Operating System)** مثل Windows أو macOS أو Linux هو البرنامج الذي يدير الجهاز:
يوزّع وقت المعالج بين البرامج، يمنح كل برنامج جزءًا من الذاكرة، يدير الملفات والمجلدات، ويتحدث
مع الأجهزة.

- **البرنامج (program):** ملف تعليمات محفوظ على القرص، مثل `python.exe`.
- **الـprocess:** نسخة من البرنامج **قيد التشغيل**، لها ذاكرتها الخاصة ومجلد عملها
  (current working directory) وقنواتها للإدخال والإخراج.

ولكل process ثلاث قنوات نصية قياسية: **stdin** (الإدخال، مثل `input()`)، **stdout** (الناتج
العادي، مثل `print()`)، و**stderr** (رسائل الأخطاء والتحذيرات).
:::

## 4. البت والبايت والنظام الثنائي

:::theory title="كل شيء أصفار وآحاد"
داخل الحاسوب، كل شيء (أرقام، نصوص، صور، برامج) مُخزَّن كـ**بتات (bits)**: قيم إما 0 أو 1،
لأن الدوائر الإلكترونية تميّز بسهولة بين حالتين (يمر تيار / لا يمر).

- **البت (bit):** 0 أو 1.
- **البايت (byte):** 8 بتات، أي `2⁸ = 256` قيمة ممكنة (من 0 إلى 255).
- **KB / MB / GB:** تقريبًا ألف / مليون / مليار بايت.

الأرقام تُكتب في **النظام الثنائي (binary)**: كل خانة قوة من قوى 2. الرقم `13` هو
`1101` = 8 + 4 + 0 + 1.
:::

:::code mode="script"
print(bin(13))            # 13 in binary
print(int("1101", 2))     # back from binary
print(2 ** 8)             # values in one byte
print(bin(255), bin(256))
:::

## 5. كيف تُخزَّن النصوص؟

:::theory title="من الحرف إلى البايت: Unicode وUTF-8"
الحاسوب لا يعرف «حروفًا»، بل أرقامًا. لذلك نحتاج اتفاقًا عالميًا:

1. **Unicode** يعطي كل حرف في كل لغة رقمًا فريدًا اسمه **code point**:
   `A` = U+0041 (65)، `ب` = U+0628 (1576)، `😀` = U+1F600.
2. **الترميز (encoding)** يحدد كيف يُكتب هذا الرقم كبايتات في الملف أو الشبكة. الأشهر
   **UTF-8**: بايت واحد للحروف اللاتينية الأساسية، بايتان للعربية، وأربعة للرموز التعبيرية.

في Python، النوع `str` هو سلسلة code points (نص مجرد)، والنوع `bytes` هو البايتات الفعلية.
`encode()` تحوّل من نص إلى بايتات، و`decode()` العكس.
:::

:::code mode="script"
for ch in ["A", "ب", "😀"]:
    data = ch.encode("utf-8")
    print(ch, ord(ch), hex(ord(ch)), data, len(data), "bytes")

word = "مرحبا"
print(len(word), "characters,", len(word.encode("utf-8")), "bytes")
:::

:::mistake
**فتح ملف بترميز خاطئ**: ملف عربي محفوظ بـUTF-8 يُقرأ كأنه ترميز آخر فيظهر نص غريب مثل
`Ù…Ø±Ø­Ø¨Ø§` (يسمى mojibake)، أو يظهر `UnicodeDecodeError`. الحل: حدّد الترميز صراحة دائمًا،
`open(path, encoding="utf-8")`.
:::

:::code mode="script"
text = "مرحبا"
raw = text.encode("utf-8")
print(raw.decode("utf-8"))      # correct
print(raw.decode("cp1252"))     # wrong encoding (old Windows default) → mojibake
:::

مختلفة، أسماء أعمدة بالعربية. التزم بـUTF-8 في كل ملفاتك، ووثّق الترميز في ملف README الخاص
بالبيانات.
:::
